# 部署脚本离线回归测试

## 运行

需要 Linux、Python 3.9+、Bash 与 GNU 工具（包括 `flock`），不需要 Docker、网络或 root：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Python 仅用于开发测试，不是生产部署的新依赖。

## 测试边界与隔离方式

测试执行完整的 `bash deploy.sh ...`，通过退出码和终端结果验证行为，不提取或替换脚本内部函数。

每个测试创建独立临时项目，只复制必要源码和模板，使用虚构域名、凭据和模拟数据，不读取生产 `.env`、运行数据或密钥。临时副本中唯一的源码替换是将硬编码 `/var/lib/dsh-nas-upgrade` 重定位到测试临时目录；生产脚本的 root-only 路径与权限约束不变。

子进程使用白名单 PATH，不继承用户代理或 Docker 环境。Docker、HTTP 请求、监听查询及权限身份等系统边界由 `fake-system.py` 模拟；未声明的模拟调用会记录并导致测试失败。文件复制和恢复在临时目录中实际执行，另有可控的复制失败注入。测试结束自动清理临时目录。

这是一套针对当前脚本的离线测试装置，**不是用于运行任意不可信 Shell 脚本的安全沙箱**。

## 当前覆盖

- 升级在配置快照后中止：正常恢复不能误报失败。
- 恢复配置时复制失败：必须报告恢复失败，不能打印恢复完成。
- 443-only、80/443、同机前置反代的正常监听集合。
- 同一 JSON 数组与不同服务器中的多监听地址。
- 多余端口、缺失端口、前置入口 wildcard 地址和空管理配置均被拒绝。
- 模拟镜像库存：只清理专用标签的无引用悬空镜像；保留其它项目、未标记历史镜像、有标签或有容器引用的镜像。
- 清理失败、读取库存失败仅警告；部署失败不清理镜像。
- 构建前基础镜像拉取成功、超时后非交互中止，以及镜像站交互选择（有 PTY 时）；Docker 与 timeout 使用替身，不实际拉镜像。
- 阶段编号、累计/总耗时、慢启动状态提示和成功/失败摘要；日志与重启命令分行。
- 非 TTY 纯文本输出；PTY 下的颜色、`NO_COLOR` 和 `TERM=dumb` 行为；token 链接仍按原方式展示。环境无法分配 PTY 时该项明确跳过，需在可用终端上补测。

## 未覆盖的真实环境验收

模拟测试不能证明 Docker/Caddy 返回值、自动 HTTPS 的运行时行为与模拟数据完全相同，也不覆盖真实镜像构建、容器切换、TLS/认证链路及完整升级回滚。后续改动应在独立测试主机上补充这些验收，不能直接在生产 NAS 上做故障注入。
